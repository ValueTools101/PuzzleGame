# Unwind — a 10-minute stress-relief break app

An Expo/React Native app for anyone who wants a quick, pressure-free break: breathe with
guided patterns and ambient sound, pop a few calming bubbles, journal or vent out loud, or
window-shop a pretend catalog with no checkout. This README is the honest handoff: what's
built and how, and exactly what's left, in order.

## Why this stack

This mirrors the [`cycle-planner-app`](https://github.com/ValueTools101/cycle-planner-app)
repo's conventions on purpose, for consistency across your Play Store apps: Expo/React
Native, no `@react-navigation` (a small hand-rolled screen switcher in `App.js` instead,
same as that repo), local-only storage via AsyncStorage, and the same honest-handoff
README/PRIVACY_POLICY.md structure.

**Unlike** the cycle planner, this app has **no login and no Firebase** — there's no
reason to gate a stress-relief tool behind an account, and skipping auth entirely means a
much simpler Play Store Data Safety form (see below) and no account-deletion flow to build.

## A note on "AI-generated audio/video, no license required"

You asked for AI-generated audio and video so nothing needs licensing. I don't have access
to an AI audio/video generation API from this environment, so I built the same *outcome*
(zero licensing risk, fully original) a different way:

- **Ambient sounds** (`src/utils/audioSynth.js`) are synthesized from scratch with plain
  math — pink/brown noise algorithms, filtered "rain" and "wind" textures, and pure sine
  tones — generated once on-device and cached as a `.wav` file. Nothing is downloaded,
  streamed, recorded, or scraped from anywhere, so there's genuinely nothing to license.
- **"Video"** is replaced with lightweight animated visuals (a breathing circle, gradient
  backdrops, floating bubbles) built with React Native's own animation APIs — no video
  files at all, which also keeps the app's download size tiny.

If you later want richer, more realistic ambient audio or nature visuals generated by an
actual AI model (e.g. via ElevenLabs, Suno, or Runway), that needs an external account and
API key I don't have — happy to wire in that integration once you have one, or to help you
review the licensing terms of whatever generator you pick.

## ✅ What's done

- Full Expo/React Native project — Home hub + 5 screens (Breathe & Sounds, Bubble Pop,
  Journal & Vent, Window Shop, About & Privacy)
- **Breathe & Sounds**: 3 selectable breathing patterns (Box, 4-7-8, Simple) with an
  animated breathing circle, plus a 5-sound ambient mixer (rain, deep hum, wind, two calm
  tones) that can play simultaneously with independent volume sliders — all procedurally
  synthesized, see above
- **Bubble Pop**: a scoring-free mini-game — bubbles float up, tap to pop, no fail state,
  no time pressure, just a satisfying counter
- **Journal & Vent**: a "Write" tab (mood-tagged text journal, local storage) and a "Speak"
  tab (record your voice with a live amplitude-reactive mic animation, then either "Delete
  & Release" — the default, cathartic flow — or "Save this one" to keep it)
- **Window Shop**: a 16-item mock catalog across 4 categories, search + category filters,
  add-to-cart with quantity steppers, and a friendly "there's no checkout, want to clear
  your cart?" flow instead of any real payment UI — avoids dark patterns and IP/licensing
  risk from real product images entirely
- A lightweight all-time "minutes unwound" counter on the Home screen, tracked across every
  mode
- `PRIVACY_POLICY.md` drafted to match exactly what the app does (no accounts, on-device
  only, no ads/analytics yet)

## ⚠️ What I could not do from here (needs your own accounts, or a real device)

I don't have a Flutter/Expo/Android build environment or a device/emulator in this session,
so **none of this has been run** — only written and carefully reasoned through. Please:

1. **Install and run it first.** `cd unwind-break-app && npm install && npx expo install --fix`
   (aligns dependency versions to the Expo SDK), then `npx expo start` — scan the QR code
   with Expo Go on your phone. Test every mode, especially microphone recording (Speak tab)
   and the ambient sound mixer, on a real device before building anything.
2. **Replace the placeholder assets.** There is no `/assets` folder yet — you'll need a
   1024×1024 icon, an adaptive icon, and a splash image at `assets/icon.png`,
   `assets/adaptive-icon.png`, `assets/splash.png` (referenced in `app.json`).
3. **Create an [Expo/EAS account](https://expo.dev)** (free) and run `eas init` in this
   folder to fill in the real `projectId` in `app.json`.
4. **Fill in the `[FILL IN...]` placeholders** in `PRIVACY_POLICY.md` — your name/company,
   contact email, and today's date.
5. **Register a [Google Play Developer account](https://play.google.com/console/signup)**
   — $25 one-time fee, if you haven't already from the cycle planner app.
6. **Host `PRIVACY_POLICY.md` at a public URL** (GitHub Pages is free) — Play Console
   requires a live link.
7. **Build the release bundle:**
   ```bash
   npm install -g eas-cli
   eas login
   eas build --platform android --profile production
   ```
8. **Create the Play Console listing** — title, description, screenshots, content rating,
   and the Data Safety form (see below).
9. **Closed testing first**, same as any new personal developer account: 20+ testers for
   14 days before Google grants production access.

## Data Safety form — how to answer it

Based on what this app actually does:
- Data collected: yes — user-generated content (journal text, voice recordings), but
  **not shared with third parties**, **not used for advertising**
- Data stored: on-device only — nothing transmitted, so "encrypted in transit" is N/A
- Data deletion: user-initiated, in-app (delete any entry/recording; uninstalling clears
  everything)

If you add a backend, analytics SDK, or ads later, **update this form and the privacy
policy to match** — Google audits for mismatches.

## Monetization — not wired in

Two realistic options, consistent with the cycle planner's approach:
- **Google Play Billing** for a one-time "extra sound packs" or "remove ads" unlock —
  `react-native-iap`.
- **AdMob** (`react-native-google-mobile-ads`) — if you go this route, keep ads off the
  Journal & Vent screen specifically, since that's where the most personal content lives;
  putting ads next to venting content is both a bad look and closer to Play's sensitive-
  content scrutiny than it needs to be.

## Repo layout note

This app currently lives as a self-contained folder (`unwind-break-app/`) inside the
`PuzzleGame` repository, because the GitHub App connected to this session doesn't have
permission to create new repositories (`403 Resource not accessible by integration`). It
does not touch or depend on anything else in `PuzzleGame` — the existing GitHub Pages
deploy workflow only ever looks at specific root-level files, so it's unaffected.

To split this into its own repo later: create an empty repo on GitHub, then
```bash
cd unwind-break-app
git init
git add -A
git commit -m "Initial import of Unwind"
git remote add origin <your-new-repo-url>
git push -u origin main
```

## Known limitations of this MVP

- **Not yet run on a device or emulator** — see item 1 above. The audio synthesis and
  recording code is written to the correct Expo APIs, but hasn't been runtime-verified in
  this session; treat it as "should work" rather than "confirmed working" until you test it.
- **Ambient loops aren't perfectly seamless** — noise-based sounds use a short fade at the
  loop point rather than a true crossfade, so there may be a very faint click every 8
  seconds. Fine for an MVP; a true crossfade loop is a reasonable follow-up.
- **No cross-device sync** — by design. Journal entries, recordings, and cart are per-
  device only, matching the privacy story above.
- **No `@react-navigation`** — same hand-rolled switcher pattern as the cycle planner app,
  fine for this flat set of screens.
- **Bubble Pop and the ambient mixer both use `expo-av`**, which Expo has been migrating
  away from in newer SDKs in favor of `expo-audio`/`expo-video`. This project pins Expo
  ~51, where `expo-av` is still the supported API — if you later upgrade the Expo SDK,
  budget time to migrate this.
